# 阶段 0 测试指南（Windows 11）

## 1. PowerShell 自动检查

安装 Node.js 20 或更新版本和 Git 后：

```powershell
Set-Location D:\Codes\WechatPushup
node --version
npm.cmd test
npm.cmd run check
npm.cmd run check:wechat
```

没有依赖，不必 `npm install`。`npm.cmd` 避免 npm.ps1 被 PowerShell 策略拦截。测试用 Node.js 内置 test runner，不需联网。

测试覆盖：触屏防抖、长按/取消、最小间隔、模式互斥、手动撤销、RGBA 解析、能力检测、校准、相对阈值、平滑、迟滞、完整周期、短遮挡/短恢复、持续遮挡、噪声、冷却、断流、低光/漂移、后台/卸载、延迟授权、延迟 start 和静默超时。

生命周期测试使用假的 wx 对象、时间和定时器，仅验证 JavaScript 控制逻辑；不代表相机驱动、原生组件或真实授权弹窗通过。`run check` 不编译 WXML/WXSS。

`check:wechat` 离线调用本机已安装工具中的 wcc/wcsc，仅编译模板/样式，不启动窗口、不上传代码。默认在 Program Files 的 Tencent 目录寻找安装；如果安装在其他目录，可传入实际路径：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-wechat.ps1 -ToolRoot 'C:\Program Files (x86)\Tencent\微信web开发者工具'
```

本机内置编译器已通过，但仍需下面的 GUI 编译运行、预览及真机测试。

可选：重新核查当前官方发布与文档，需要联网，输出只到忽略目录 `.audit/`：

```powershell
# 若系统允许执行本地脚本：
.\scripts\audit-wechat-apis.ps1

# 若本地策略阻止脚本，可仅对本次进程放行：
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\audit-wechat-apis.ps1

# 固定到本次报告的类型包版本：
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\audit-wechat-apis.ps1 -Version 5.3.1
```

脚本只下载官方文档/声明包、验证 tarball 的 SHA-512 并读取声明，不运行第三方包，不改变系统策略或项目运行依赖。

## 2. 微信开发者工具导入与编译

1. 打开当前稳定版微信开发者工具，微信扫码登录。选择导入“小程序”，项目路径为 `D:\Codes\WechatPushup\experiments\optical-demo`；不选择小游戏、插件或云开发模板。阶段 1 后，仓库根目录用于正式工程。
2. 工具读取实验目录自己的 `project.config.json`，其 `miniprogramRoot` 为 `./`，对应包含 app.json 的实验目录；不把 tests/docs 当作运行代码。
3. 无 AppID 可先用现有 `touristappid` 进行本地编译与模拟；真机预览使用自己的小程序 AppID，并将扫码微信设为开发者/有相应权限的成员。测试号/游客模式的能力不能替代真实 AppID 权限与隐私配置。
4. 在工具本地设置选择稳定基础库 ≥ 2.32.3，保持 ES6 编译开启。无需 npm 构建，不需要配置服务器、云环境或关闭合法域名校验。
5. 点击编译。应出现单页“光学计数实验室”，默认不显示 camera 实时预览。记录开发者工具版本、所选基础库及编译是否成功。
6. 若编译失败，先在 Console 记录**首条错误**和文件行号；请反馈该错误，不把 Node.js 静态检查视为编译通过。

## 3. 在模拟器验证算法与触屏

1. 点击“清零”，选择“正常周期”，点击播放。约 11 秒后本段应新增 3 次，模式明确写有“模拟信号”。
2. 清零后依次播放“快速抖动”“持续遮挡”“环境过暗”“校准不稳定”，每个应新增 0 次。后三者应报对应原因并切触屏；抖动播完直接停止。
3. 点击触屏实验，下方绿色大区域轻触 5 次（间隔约 1 秒），应计 5 次；按住 3 秒应只计 1 次。600 ms 内快速重复触碰被忽略，松开/取消后可重新触碰。
4. 手动 +1、撤销 −1、暂停、恢复、清零分别检查；撤销不得出现负数，暂停期间触屏不计。
5. 播放模拟时触碰大区域不应增加自动次数；只有显式手动 +1 能调整，切触屏后模拟应立即停止。
6. 工具中摄像头按钮按设计不可用于证明手机硬件，显示使用 Android/iPhone 真机的说明。即使其他环境能显示电脑摄像头，也不纳入本实验真机结论。

默认参数的预期只适用于默认场景；若调整了灵敏度/间隔，记录参数再比较，不把改参后的表现与默认测试混用。

## 4. 手机预览前配置

1. 将 `experiments/optical-demo/project.config.json` 的 `appid` 改为自己的小程序 AppID（可使用正式工程已配置的 AppID），确认工具登录的微信和手机微信具有相应开发权限。
2. 在[微信公众平台](https://mp.weixin.qq.com/)小程序管理后台，找到用户隐私保护指引配置，填写与真实行为一致的相机用途：用户主动开启后，画面仅在设备内存中提取亮度以验证遮挡计数；不拍照、录像、保存或上传画面。后台入口名称可能随版本调整，以当前控制台为准。
3. 本 Demo 实现了隐私同意按钮及 `scope.camera` 授权，不申请登录、麦克风或相册；后台隐私声明与硬件授权是不同环节，不能只改 app.json 就认为配置完成。
4. 点击开发者工具“预览”，手机微信扫码。必要时用真机调试查看控制台，但最终也要在普通预览状态重测，避免调试开销影响采样。
5. 首次运行页面应没有实时画面。点击“主动开启前置摄像头并校准”，按提示同意隐私指引并允许相机。若已授权可能不再弹框，这是正常行为。
6. 如果拒绝，页面应显示原因并切到触屏；可点击“权限设置”调整小程序权限。系统若禁止微信使用相机，还需到手机系统设置允许微信使用相机，再主动重试。不要反复弹授权逼迫同意。

初始化/授权等待上限为 12 秒；阅读隐私或调整设置耗时较长时可能先降级，可返回后主动重试。这里是实验超时，不是权限是否支持的最终判定。

## 5. 真机测试顺序

Android 和 iPhone **分别**执行以下步骤，填写 [validation-results.md](validation-results.md)。没有其中一个平台时保持其结果为“待真机验证”。

### A. 数据通路与空镜校准

1. 手机固定平放、屏幕朝上、前置镜头无遮挡。在均匀稳定照明下开启摄像头。
2. 预览应来自前置镜头；约 3 秒后显示 READY、非零基准值、实际帧宽高、持续增加的已处理信号数。
3. 静置 60 秒应为 0 次新增。观察比值是否约在 1 附近；若持续漂移、很暗或不稳定，记录后更换环境重新开启。
4. 仅看到预览不算取帧成功；必须有实际数值和信号数变化。记录尺寸，不假设 small 对应固定分辨率。

### B. 手掌遮挡与完整周期

1. 遮住前置镜头约 0.8–1 秒，再移开约 1–1.5 秒，做 10 个周期。计数只能在恢复足时后增加，预期新增 10 次。
2. 只遮住不移开：应不增加次数，持续约 6 秒后应要求重校准并切触屏。移开后主动重新开启。
3. 快速掠过镜头、在阈值附近抖动，预期不重复增加；长时间恢复明亮不得持续增长。
4. 同时用手触碰大区域，摄像头模式下不应叠加触屏计数；手动 +1 是显式纠错。

### C. 实际俯卧撑可用性

1. 先用手掌确认通路，再以手机屏幕朝上做实际俯卧撑，调整手机相对头部和前置镜头的位置。
2. 连做 3 轮，每轮实际 10 次，轮间正常休息；记录每轮读数、漏计/误计、摆位、光照与参数。
3. 若人体接近时比值不降反升，或降幅不足、恢复不稳定，这可能是曝光/取景限制；保存数值诊断和现象，不能靠宣布成功或无限提高灵敏度解决。
4. 灵敏度每次只改一个值，保持手机不动、重新校准，再重复。UI 数值四舍五入，实际阈值使用配置精度。
5. 手掌通过但实际动作失败：结论应为“取帧通路可行，实际动作计数不可用/仍待调参”。本实验不评估运动姿态是否标准。

### D. 生命周期、错误与离线

1. READY 或 DARK 时切微信后台/锁屏；确认系统相机使用指示停止（指示展示和延迟因系统而异），后台不继续计数。
2. 返回应重新校准；不能把离开前的半次遮挡当完整周期。次数应保留。
3. 摄像头运行中切触屏、点击停止、暂停、离开页面；观察指示停止，计数无旧源叠加。连续重开 5 次应每次都得到新校准。
4. 触屏/模拟进后台会停止，回来需主动重启；摄像头会话恢复也必须重新校准。页面关闭/重新进入后次数清空。
5. 测试拒绝相机、系统相机权限关闭、暗光、明显改变光源、相机被中断；应有原因和可用触屏降级。帧静默超过 3 秒自动降级。
6. 预览代码已加载且权限配置完成后断网，验证触屏、模拟、摄像头计数链路无需业务网络。扫码预览/首次加载本身仍由微信负责联网分发代码。
7. 连续使用 5 分钟，观察卡顿、抽样耗时、温升与耗电；这不等同于精确测量总 CPU 或相机功耗。

## 6. 隐私与结果反馈

开发者工具 Network 面板应没有本 Demo 发起的业务请求；源码未调用 wx.request/uploadFile/connectSocket、拍照/录像或 storage API。微信宿主自身行为不在本 Demo 控制范围内，不能据此声称整个微信没有任何网络行为。

“复制数值诊断”是主动复制 JSON，仅含设备/版本、信号、参数、次数和错误，不含图片。诊断中的硬件状态默认仍为待验证，真正验收由人工结果表填写。建议反馈：
