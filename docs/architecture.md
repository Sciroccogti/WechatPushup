# 全项目技术方案与阶段边界

用户反馈阶段 1“测试无误”，并明确授权进入阶段 2。首页、运动项目选择与基础训练准备界面已建立；计数/计时、计划和数据业务仍按后续阶段实现，光学硬件结论保持待真机验证。

## 产品边界

微信原生小程序，WXML/WXSS/JavaScript/JSON，无框架、登录、云函数、数据库或运行所需网络。训练与数据分析本地完成。首版配置四种项目：俯卧撑、仰卧起坐、深蹲按次，平板支撑按秒，各自维护能力、计划和历史。新增运动通过项目配置扩展，不复制页面业务算法。

光学检测只能发现画面亮度周期，不能判断动作、幅度或有效次数。先以俯卧撑摆位验证，不推断它适用于仰卧起坐或深蹲。若真机不能稳定工作，正式产品保留光学接口，以触屏/手动为主；计时项目不调用摄像头。

## 分层与职责

1. **页面层**：视图、事件、中文提示、无障碍与安全区域；不写训练策略。
2. **训练流程层**：评估、工作组、组间休息、暂停、跳过、结束状态机。使用时间戳/截止时间计算时长，定时器仅刷新界面，避免后台节流造成时间漂移。主动训练进后台暂停，回来由用户确认继续。
3. **独立计数层**：统一 `start/pause/resume/stop/reset/addCount/undoCount/getCount`。TouchAdapter、OpticalAdapter、ManualAdapter 接入；只有一个主要自动来源。光学提取器和状态机分离，不依赖训练引擎。
4. **训练领域层**：ExerciseRegistry、能力评估、长期计划与调整策略。确定性输入/输出，注入日期与策略参数，Node.js 可测试。
5. **数据层**：Repository → StorageAdapter → LocalStorageAdapter。未来 CloudBackupAdapter 独立扩展，首版无请求、域名、凭证或同步任务。

## 长期计划设计

- 首次选择项目，记录最大有效次数/秒数；允许手动校正，保存评估日期与版本。单次最大值不直接等同于每天可承受训练量。
- 每个计次训练日由策略生成五组目标及组间休息，末组有目标并允许按状态结束；不将示例次数写死在页面。
- 使用近期完成率、有效训练次数、疲劳反馈、连续训练天数与恢复间隔选择“增加、维持、降低、休息”。不机械每日递增；未训练不自动升级。
- 以完成训练周期触发减量和重新评估，返回可解释的原因代码及中文说明。不同运动独立进展；训练策略参数在阶段 5 单独评审及验证。
- 组目标可调整、可跳过，未完成真实记录，不把跳过当成功。达到目标自动进入休息；允许延长/提前结束休息、暂停与恢复。时间和次数严格区分单位。
- 计划算法是一般运动工具规则，未来实现前核对训练依据，不在阶段 0 给出未经验证的个体处方。

## 数据与未来备份契约

正式版本使用带 `schemaVersion` 的数据封装，记录至少包含稳定 `id`、`exerciseId`、开始/结束时间、当地日期、目标/实际单位、每组目标/实际/状态、实际休息时长、计数模式变化、疲劳、完成率、策略版本与更新时间。汇总结果由记录计算，避免删除/修改记录后累计值不一致。

本地适配器对 `get/set/remove/export/import` 提供统一语义；捕获容量不足、读写异常和损坏数据，不静默清空。升级以显式迁移处理未知版本，先保留原数据再迁移；导入前验证版本、结构与 ID，按稳定 ID 幂等去重，测试失败回滚与重复导入。

未来备份：设备 ID + 随机唯一记录 ID、修订号/更新时间、删除墓碑、协议版本与冲突策略；不按日期或数组下标覆盖记录。恢复应先校验、备份当前本地数据，再按 ID 合并；同 ID 不同修订保留可恢复的冲突副本。CloudBackupAdapter 先仅设计契约，阶段 0 不创建占位网络实现。

## UI 与平台

中文、少动画、大触区、明显模式与暂停状态。训练页面可深色、无广告；安全区留白，不依赖未授权第三方图标/图片。统计曲线可用原生 canvas 或简单自绘，不因画图引入整套框架。正式 UI 的触屏“灵敏度”定义为事件时序/最小间隔，不能声称微信能可靠读取鼻尖压力。
