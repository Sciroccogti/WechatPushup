# 随身健身教练

微信原生小程序，WXML/WXSS/JavaScript/JSON，无第三方框架、登录或后端。当前为**0.5.3训练大按钮**，保留阶段5能力评估、长期计划与五组训练，并按用户要求合并项目选择、支持传感器与触屏并行、加入大面积触屏及涟漪反馈。

已针对“开始按钮无响应、平板需再点一次”的反馈修复事件隔离和刷新逻辑：按钮使用完整触摸/点击链，待机和暂停不轮询刷新，运行时只更新变化字段；涟漪改用小图层扩散。四项目一次点击启动的模拟回归通过，真机响应需复核。

训练操作按钮已明显放大：开始/继续整行至少176rpx，暂停/结束至少160rpx，其他训练操作至少136rpx；休息页同步放大字号、触区与间距。详见[按钮尺寸调整](docs/large-training-buttons.md)。

## 现在的流程

底部训练页直接选项目 → 查看长期计划 → 首次能力评估（实际测试或手动填写）→ 选择计数方式 → 五组训练 → 自动组间休息 → 总结与疲劳反馈 → 保存并更新下次计划。

- 项目卡片不再显示1–4编号，独立选择页已删除；底部训练页和执行训练页都支持排序，执行页暂停后可直接更换项目。
- 俯卧撑：光学实验模式可与触屏同时计数，保留手动纠错；仅该运动可以开启摄像头。
- 仰卧起坐、深蹲：陀螺仪实验模式可与触屏同时计数，保留手动纠错。按用户确认的摆位，手机竖向固定在胸前或上身，默认X轴，可切自动选轴。静放地面不能检测动作；深蹲上身转动较小可能漏计。
- 四个项目开始后提供大面积触摸区域（主要区域至少60vh）：有效触碰在落点扩散涟漪并切换绿色系背景，显示+1或计时中；控制按钮不误加数。
- 平板支撑：轻触大区域或按钮开始/继续计时；计时中触屏只播放反馈，不暂停或重置。无需传感器，计划训练支持五组计时。
- 传感器与触屏共用去重窗口；传感器周期中已触屏计数时，该周期完成事件不再加一。主要传感器仍保持单一。
- 达到目标自动进入休息；休息倒计时结束提示就绪，主动开始下一组。可提前结束/延长休息、暂停、跳过、调整目标和手动纠错。
- 默认按累计训练时长排序，保留最近使用选项。底部训练页、执行页和设置都能切换；只累计实际训练，休息、暂停、校准、后台及浏览不计入。
- 光学阈值仍可在设置中边测试边调，拖动即时应用、松手保存。相机与陀螺仪实际动作效果均待真机验证。

## 快速运行

微信开发者工具打开 **`D:\Codes\WechatPushup`**，确认小程序根为 `miniprogram/`，使用已有AppID与稳定基础库（建议≥2.32.3）。无需云开发、npm构建或服务器。

1. 选择运动进入计划页；首次点击能力评估，可填写当前已知最大能力，或进入一次实际测试后结束并确认结果。
2. 计划页显示五组目标、休息与调整原因。恢复期显示下次训练时间；不要求每天高强度训练。能力测试后也安排恢复。
3. 进入五组训练，先用触屏/手动检查完整流程；平板支撑按秒计时。训练/休息页之间替换导航，避免堆积页面栈。
4. 总结页选择疲劳并保存；离开总结时按当前选择自动保存，未选择时按“适中”处理。同一结果不会重复推进计划。
5. 真机预览用微信扫码。相机需要在小程序后台如实配置隐私用途，用户主动同意后才能采集；陀螺仪不申请虚构的相机/传感器scope。后台、暂停、休息或离开都会停采集。

目前保存能力、长期进展和训练结果供计划调整，不自动删除旧结果；**历史浏览/统计、分块与导出导入仍在阶段6**。当前进行中的会话只在内存，后台暂停可继续，进程被系统清除后不能恢复未结束会话；累计时长训练中约每5秒检查点保存，退出时补齐。

## PowerShell 检查

需要Node.js≥20，没有包依赖，无需npm install：

```powershell
Set-Location D:\Codes\WechatPushup
npm.cmd test
npm.cmd run check
npm.cmd run check:wechat
npm.cmd run simulate -- 180
```

`npm.cmd`避免PowerShell脚本执行策略限制。simulate输出半年策略演进示例，假设能力20次、每3天训练且稳定完成，**不是人体训练效果预测**。

已通过80项测试、静态检查和微信内置编译器检查（正式14份WXML/15份WXSS，Demo1份WXML/2份WXSS）。覆盖并行触屏/传感器去重、落点动画生命周期、控件事件隔离、就地选项/排序，以及半年计划模拟、完整五组/计时、存储等回归。模拟、编译与Android/iPhone真机验证是不同级别。
